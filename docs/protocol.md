# 러너 ↔ 시뮬레이터 프로토콜

루프백 TCP, 줄 단위 텍스트. 연결 1개가 시나리오 1개이며 `run` 이후 응답을 받고 끝난다.
시뮬레이터는 시작할 때 `LISTENING <포트>` 한 줄을 표준 출력에 낸다 (포트 인자를 생략하면 OS가 빈 포트를 고른다).
파서 구현은 `core/protocol.cpp`이며, 외부 입력으로 보고 모든 필드를 엄격하게 검사한다.

## 요청 (러너 → 시뮬레이터)

| 줄 | 뜻 |
| --- | --- |
| `mode virtual\|realtime` | 가상 시간(결정적) 또는 실제 시간 |
| `duration_ms N` | 시뮬레이션 길이 (≤ 3600000) |
| `can_tx 노드 ID 확장 주기ms 오프셋ms DLC 16진데이터` | CAN 주기 송신. 데이터가 없으면 `-` |
| `can_sub 노드 키\|*` | CAN 수신 구독 (키는 아래 참고) |
| `can_rsp 노드 요청키 응답ID 확장 지연ms DLC 16진데이터` | 요청 프레임을 받으면 지연 후 응답 |
| `m_rt 노드 주소 무응답(0/1) 상태비트값 16진워드들` | 1553B RT. 워드는 4자리씩 이어 쓴다 |
| `m_bc 노드 RT T/R(0/1) 서브주소 워드수 주기ms 오프셋ms 16진워드들` | 1553B BC 주기 전송 |
| `run` | 실행 |

- 숫자는 부호 없는 10진수만 허용한다 (`-1`, `0x10`, 공백 포함 값은 오류).
- 필드 수가 정확히 맞아야 한다. 16진 데이터는 바이트당 2자리, 워드당 4자리이며 데이터 길이는 DLC 이하.
- 노드 이름은 공백 없는 영문/숫자/밑줄.
- 한 줄은 64KiB, 설정 줄은 시나리오당 100000줄까지.

## 응답 (시뮬레이터 → 러너)

- `ev <ts_ns> <tx|rx|to> <노드> <can|m1553> <키> <16진 raw>` 반복
  - `to`: 1553B에서 RT가 응답하지 않아 BC가 기록한 타임아웃
  - 키: CAN은 식별자이며 확장(29비트) ID는 `0x80000000` 비트(SocketCAN `CAN_EFF_FLAG`)를 붙인다.
    1553B는 `(RT<<10)|(T/R<<9)|서브주소`
  - raw: CAN은 SocketCAN 16바이트, 1553B는 20비트 워드를 4바이트 리틀엔디언씩 이어 붙인 것
- `done <개수>` 로 끝.
- 잘못된 줄이나 프레임, 이벤트 상한 초과(같은 시각 10000건, 전체 1000000건)는 `error <메시지>` 한 줄.

러너는 시뮬레이터가 응답하지 않거나(`duration_ms` + 15초) 형식이 깨진 응답을 보내면 그 시나리오를 ERROR로 두고
시뮬레이터 프로세스를 다시 띄워 다음 시나리오를 진행한다.
