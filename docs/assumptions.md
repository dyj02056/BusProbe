# 모델링 범위와 가정

공개 자료 수준의 일반 모델이며 특정 장비의 규격 원문을 근거로 하지 않는다.
1553B 비트 배치(상태 워드, 동기 패턴)는 공개 튜토리얼 수준의 지식으로 구현했으므로, 실제 장비와 맞출 때는 해당 규격 원문으로 다시 확인해야 한다.

## 포함

- CAN 2.0A/B: 표준 11비트, 확장 29비트, RTR, DLC 0~8, SocketCAN 호환 16바이트 직렬화
- 1553B: 20비트 워드(동기 3 + 데이터 16 + 홀수 패리티 1), 커맨드 워드, 상태 워드 주요 비트,
  BC→RT, RT→BC, 방송(주소 31), RT 무응답 타임아웃
- 방송을 받은 RT는 다음 상태 워드 응답 1회에 `broadcast_received` 비트를 싣고 지운다
  (규격의 "다음 유효 명령에서 갱신" 동작을 단순화. 상태 워드 송신 모드 코드는 모델링하지 않는다)
- 가상 시간(결정적)과 실제 시간 두 모드. 같은 시각 CAN 프레임은 ID 값이 낮은 쪽이 먼저 전달된다
  (표준/확장 ID의 실제 중재 비트 비교는 모델링하지 않는다)
- 표준 ID와 확장 ID는 값이 같아도 다른 메시지로 구분한다
- 폭주 방지: 같은 시각 이벤트 10000건, 전체 이벤트 1000000건을 넘으면 시뮬레이션을 오류로 끝낸다

## 제외 (필요해지면 추가)

- CAN FD, 비트 타이밍, 비트 스터핑, CRC, 에러 프레임 (요구사항 REQ-CAN-007은 일부러 시험 없음으로 둠)
- 1553B 응답 시간(마이크로초), 전기적 특성, 이중 버스 절체, RT→RT 전송, 모드 코드
- 프레임 전송 시간: 송신과 수신은 같은 시각에 일어난다 (지연은 `respond.delay_ms`로만 모델링)
- 신호 해석: 인텔(리틀엔디언) 바이트 순서만
- DDS: 이번 범위에 구현하지 않았다
- 실시간 모드는 시뮬레이터 스레드 1개가 절대 시각 기준으로 대기한다. 윈도우 기본 타이머 해상도(약 15ms) 때문에 지터가 크다
