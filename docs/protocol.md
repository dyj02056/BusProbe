# 러너 ↔ 시뮬레이터 프로토콜

루프백 TCP, 줄 단위 텍스트. 연결 1개가 시나리오 1개이며 `run` 이후 응답을 받고 끝난다.
시뮬레이터는 시작할 때 `LISTENING <포트>` 한 줄을 표준 출력에 낸다 (포트 인자를 생략하면 OS가 빈 포트를 고른다).

## 요청 (러너 → 시뮬레이터)

| 줄 | 뜻 |
| --- | --- |
| `mode virtual\|realtime` | 가상 시간(결정적) 또는 실제 시간 |
| `duration_ms N` | 시뮬레이션 길이 |
| `can_tx 노드 ID 확장 주기ms 오프셋ms DLC 16진데이터` | CAN 주기 송신. 데이터가 없으면 `-` |
| `can_sub 노드 ID\|*` | CAN 수신 구독 |
| `can_rsp 노드 요청ID 응답ID 확장 지연ms DLC 16진데이터` | 요청 프레임을 받으면 지연 후 응답 |
| `m_rt 노드 주소 무응답(0/1) 상태비트값 16진워드들` | 1553B RT. 워드는 4자리씩 이어 쓴다 |
| `m_bc 노드 RT T/R(0/1) 서브주소 워드수 주기ms 오프셋ms 16진워드들` | 1553B BC 주기 전송 |
| `run` | 실행 |

ID, 숫자는 10진수. 노드 이름은 공백 없는 영문/숫자/밑줄.

## 응답 (시뮬레이터 → 러너)

- `ev <ts_ns> <tx|rx|to> <노드> <can|m1553> <키> <16진 raw>` 반복
  - `to`: 1553B에서 RT가 응답하지 않아 BC가 기록한 타임아웃
  - 키: CAN은 식별자, 1553B는 `(RT<<10)|(T/R<<9)|서브주소`
  - raw: CAN은 SocketCAN 16바이트, 1553B는 20비트 워드를 4바이트 리틀엔디언씩 이어 붙인 것
- `done <개수>` 로 끝. 잘못된 줄이나 프레임은 `error <메시지>` 한 줄.
